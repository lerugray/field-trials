## Verdict

**DEFECTS FOUND — 1 BLOCKER, 6 DEFECT, 5 FRICTION.**

The build is stable, polished, and rules-correct in the engine. It is not playable as a game,
for one reason: **you cannot attack by clicking.** Combat only fires on a drag or an arrow key.
Since victory requires eliminating enemy units, and the shipped opponent never advances, no
normal game can reach a conclusion.

Worth knowing up front: the M6 report states a fresh-profile automated runtime capture "could not
be completed in this managed macOS lane" (Chromium aborting at Mach-port rendezvous), and defers
acceptance to operator play on that basis. **That premise does not hold.** Chromium launched
first try and drove 220 turns of play. The whole battery below was automatable.

## Findings

### BLOCKER

**B1 — Clicking an enemy unit does not attack it; it selects the enemy instead.**
This is the documented path. Help says: *"Select a friendly unit, then point to an enemy in range.
The inspection card shows every contributing value before you commit."* The inspection card appears
and is correct — `Attack 8 / Defense 0 / Margin 8 / Result destroyed` — and then the click does
nothing to the enemy. The SELECTED UNIT card flips to `Side: South`, i.e. the player's own selection
is silently replaced by the enemy's. Clicking again never commits.

Measured, all on the Comms Audit position with a winning margin showing:

| How the player tries to attack | Combat resolves? |
|---|---|
| Click the ringed target (documented) | **no** |
| Click it twice | **no** |
| Click the enemy with nothing selected | no — selects the enemy |
| **Drag** own unit onto it | **yes** — `attack f18 destroyed (8 vs 0)` |
| **Arrow key** into it | **yes** — same log line |

Root cause, in `onPointerUp`: `onPointerDown` sets `dragId` to whatever piece sits under the
cursor — *including an enemy piece*. On release, because pointer-down and pointer-up landed on the
same occupied square, the first branch tests `draggedPiece.x === square.x && draggedPiece.y === square.y`,
which is true, and takes `doSelect(dragId)`. The enemy-target branch inside `handleMoveOrAttack`
is therefore unreachable by a click. A guard that only claims `dragId` for own-side pieces, or a
side check before `doSelect`, closes it.

Why it is a blocker rather than a defect: combat is the game's core verb, victory requires
eliminating enemy units or taking arsenals, and the engine (D5) never comes to you. Across 220
turns of play not one shot was fired by either side.

### DEFECT

**D1 — Loading the same save file a second time silently does nothing, and the UI says it worked.**
First load restores correctly. Perturb the position, pick the *same* file again: the board is not
restored, no error appears, and the status line still reads `Save file loaded.` Root cause: the
`fileInput.value = ''` line in `loadFromFile`'s `reader.onload`/`onerror` is outside the scope where
`fileInput` is declared (it is a `const` in the panel builder), so it throws and the input is never
cleared — meaning re-selecting the same filename fires no `change` event. This directly falsifies
the M6 report's line *"File load can repeat the same file."* The one statement that promises it is
the one that throws.

**D2 — Uncaught page error on every file load:** `ReferenceError: fileInput is not defined`.
Same root cause as D1. It fires after the state is applied, so the first load still works, but a
shipped RC throws on a routine action. This is the only console error produced anywhere in the
battery.

**D3 — After an attack, the UI still offers moves it will refuse.** The rule is enforced correctly
— a move attempted after the turn's attack does not execute. But the TURN card still reads
`Moves left 5` and the board still paints six legal-move dots. Clicking them does nothing, with no
message. The rule is right and the display contradicts it.

**D4 — The opponent does not play. It shuffles two units back and forth forever.**
The engine's move lines alternate between one set and its exact reverse:

```
55.S: I o1-p1, I k3-l3
56.S: I p1-o1, I l3-k3
57.S: I o1-p1, I k3-l3
58.S: I p1-o1, I l3-k3
```

Share of the engine's turns spent on one of two mutually-reversing move-sets: **gameA 69/80 (86%),
gameB 66/80 (83%), gameD 43/60 (72%)**. It never advanced on the board, never contested a square,
never attacked, and lost no pieces. Reported search depth is **1** (450 nodes, 560 ms of a 900 ms
budget). The build is honest about being shallow — it says so in Help and makes no Stockfish claim
— but M5's acceptance was *"depth-N must beat depth-N-1 over ≥20 self-play games"* and Ray's
direction was *"particularly interested to see how the AI turns out."* At depth 1 the chosen line
is a null cycle.

**D5 — `Preset: test` is shown to the player as the name of the game they are playing.**
The TURN card reads `Preset test` on first open. It still reads `test` after clicking **Opening**,
which Help describes as *"Opening starts a full game."* The other two presets label themselves
sensibly (`comms-drill`, `comm-cut`). The source is blunter than the UI: the function is
`testPreset()` and its comment says *"This convenience opening is not a canonical position."*
On a build whose headline chrome is `RULES: 92.7% VERIFIED`, the only full-board start is a
self-declared non-canonical position presented as the Opening.

**D6 — "Sandbox free move" removes the move dots and does not grant free movement.**
With it on, a unit that had 6 legal-move dots shows **0**, the SELECTED UNIT card prints the literal
string `sandbox` where the legal-move *count* belongs, a click on a distant square (m10) does
nothing, and only the already-legal adjacent moves still work. So it withdraws the guidance without
delivering the freedom its name promises.

### FRICTION

**F1 — Waiting on the engine.** 3.4–5.6 s per turn on average, up to 8.8 s, to watch two units
step sideways and back.

**F2 — No stalemate or no-legal-move detection.** `findVictory` tests only elimination and arsenal
capture; the string "stalemate" does not occur in the build. A player who over-extends and strands
their army out of supply can press End Turn indefinitely with no signal that the position is dead.
Stated as friction rather than defect because I reached that state through deliberately aggressive
advancing, and the engine's passivity compounds it — but there is no code path that would ever tell
a player.

**F3 — `End Turn` stays enabled after the game is decided.** Hint correctly disables and the move
dots correctly stop; End Turn does not.

**F4 — The principal line renders as `MA v18`.** The engine card gives DEPTH, NODES and MS clearly;
the principal line is compressed to the point of being unreadable — no from-square, no separator.

**F5 — The session status line is stale.** It stays `Save file loaded.` across a Restart and across
the failed second load of D1, so it actively misleads at the one moment it matters.

## What still genuinely needs the operator's eyes

Roughly ten minutes, and only these. Everything above is settled and needs no re-checking.

1. **Fix B1 first, then judge the game.** Until clicking attacks, no play session tells you anything
   about the design. (2 min to confirm the fix: open Comms Audit, click the ringed enemy, expect
   `attack f18 destroyed`.)
2. **The register call.** REGISTER-NOTES asks for austere cream/ops-red, lichess-class polish,
   "digital operational table, not web app." Look at `loa/t1-02-after-walkthrough.png`,
   `t1-04-pieces-nato.png` and `t1-04-pieces-chess.png` and say whether the palette and the three
   piece styles land there. Automation confirmed all three *render*; only you can say whether the
   NATO and chess variants read as the same product.
3. **Is a depth-1 shuffling opponent shippable as v1?** Mine is a measurement, not a taste call.
   Either the engine needs real depth or the UI should stop presenting it as an opponent.
4. **`Preset: test` (D5) — your call on what the Opening should be.** Renaming the label is trivial;
   deciding whether v1 ships a non-canonical convenience opening is a design decision.
5. **Sound.** Procedural effects and the analysis tone were toggled but never listened to. Nothing
   in this battery can judge them.
6. **Feel of the supply mechanic.** Advancing carelessly strands your army permanently (F2). Whether
   that is bracing or just punishing is a design judgement.
